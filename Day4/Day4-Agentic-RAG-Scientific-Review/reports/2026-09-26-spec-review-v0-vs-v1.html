Spec compliance review

10 KPIs, two versions, one working tree

Every KPI in SPEC.md scored against real evidence read from both versions of the agentic RAG app — no verdict without a file, a test result, or a log line behind it.

VERSION 0 — acd2d38

Initial commit. FastAPI + React app calling OpenRouter. No observability, no load testing, no SPEC.md.

VERSION 1 — working tree

Groq replaces OpenRouter with 429 retry handling, a full OTel → Grafana/Prometheus/Loki/Tempo stack, k6 load testing, and a knowledge-vault/.

Overall verdict

Version 1 is a substantial, evidence-backed improvement on the axes that were previously absent or thin: observability, rate-limit robustness, performance visibility, and documentation. Test coverage grew to 34 passing. But the citation-format gap and the log-redaction gap in orchestrator.py / logging.py carry over byte-for-byte unchanged — this is a real step forward, not a finished product.

Biggest remaining gaps in Version 1

Real weaknesses this session's work did not touch — not a hedge, an actual backlog.

Citation format gap is unfixed.

CITATION_PATTERN in orchestrator.py still silently drops any citation outside the exact bracket format — no log, no fallback, no test for a malformed-but-plausible tag.

Redaction filter still only guards string messages.

RedactSensitiveFilter.filter() is a no-op on non-string record.msg. The new OTLP log export path rides on the same unfixed filter, widening the blast radius if it's ever bypassed.

No SLO assertions in the load test.

agentic_rag.js checks for HTTP 200 and a "final" event, but no thresholds block — closer to a smoke test than a performance gate.

knowledge-vault/ and SPEC.md are unvalidated against drift.

Nothing currently checks these docs stay in sync as the code changes further.
