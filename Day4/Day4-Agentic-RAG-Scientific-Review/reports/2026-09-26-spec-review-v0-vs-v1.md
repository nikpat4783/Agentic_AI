# Spec compliance review: Version 0 vs Version 1

**Version 0** = commit `acd2d38` (initial commit: FastAPI+React agentic RAG app
calling OpenRouter; no observability, no load testing, no `SPEC.md`).
**Version 1** = current working tree (uncommitted changes included): Groq
replaces OpenRouter with retry-on-429 handling, a full OpenTelemetry +
Grafana/Prometheus/Loki/Tempo stack (`observability/`, `backend/app/observability.py`),
a k6 load-testing setup (`loadtest/`), an extended `mcp-server/`, a
`knowledge-vault/` of architecture docs, and `SPEC.md` itself.

## Overall verdict

Version 1 is a substantial, evidence-backed improvement over Version 0 on the
axes that were previously either absent or thin: observability went from
"basic Python logging only" to full OTel traces/logs/metrics wired through a
real collector stack with a load-bearing metric naming contract; robustness
gained an actual retry loop for the one failure mode the spec calls out by
name (429/rate-limit), with five new tests proving both the retry-succeeds
and retry-exhausted paths; performance moved from "unmeasured" to "has an
opt-in, explicitly cost-gated k6 script with a real latency/error-rate
check"; and documentation/maintainability gained a 10-file `knowledge-vault/`
and this `SPEC.md` itself as a fixed target. Test coverage grew from an
implied ~30ish tests to 34 passing (verified by running `pytest -q` against
the current tree just now). That said, several load-bearing weaknesses carry
over unchanged from Version 0 — most importantly, the citation-extraction
regex and its silent-drop-on-format-mismatch behavior in
`backend/app/agent/orchestrator.py` is byte-for-byte identical between
versions, and the redaction filter's "only patches `record.msg` if it's a
`str`" gap is likewise unchanged. Version 1 is a real step forward, not a
finished product.

## Biggest remaining gaps in Version 1

- **Citation format gap is unfixed and unchanged**: `CITATION_PATTERN` in `backend/app/agent/orchestrator.py` still silently drops any citation the model emits outside the exact `[PMID:...]`/`[arXiv:...]` bracket format — no logging, no fallback, no test asserting behavior on a malformed-but-plausible tag. This is the single biggest groundedness risk and nothing in this session's diff touched it.
- **Redaction filter still only guards `str` messages**: `RedactSensitiveFilter.filter()` in `backend/app/utils/logging.py` is a no-op whenever `record.msg` isn't a plain string (e.g. logged as `%s`-style args, or a dict/exception object) — same gap in both versions, and now there's an additional OTLP log export path (`observability.py`) riding on top of the same unfixed filter, which widens the blast radius if it's ever bypassed.
- **No SLO/threshold assertions in the load test**: `loadtest/scripts/agentic_rag.js` checks for HTTP 200 and presence of a `"final"` event but asserts no latency or error-rate threshold (no `k6` `thresholds` block), so "known behavior under load" is closer to "runs without crashing" than a real performance gate.
- **`knowledge-vault/` and `SPEC.md` are new and unvalidated against drift**: nothing currently checks that the 10 knowledge-vault docs or `SPEC.md` stay in sync with code as it changes further; e.g. `Observability.md` already references a `start_observability_stack` MCP tool on `app-dev-orchestrator` that isn't independently verified in this review.
